**Per-account checkpoints and restore points** — the backup/restore model of the Velocity headless
platform, now in KISS Backup Client.

### New
- **Back up an account now** (console) / `kiss-backup checkpoint <account>` — an on-demand,
  labelled restore point for one account: **files and databases from the same moment**,
  databases only, or files only. Take one before a plugin update or a migration.
- **Restore points per account** — the restore screens list the account's scheduled backups,
  its checkpoints (by label) and the safety copies of earlier restores, newest first.
  `kiss-backup points <account> files|db` prints the same list.
- **Databases have their own restore-point list** — the account's database checkpoints and the
  daily database dumps. Restoring from a full checkpoint brings files and databases back from
  the same moment.
- **Undo is a restore point** — the safety copy taken before a restore can be picked like any
  other point.
- **Second confirmation**: type the account name before a restore runs. Restores and checkpoints
  record who ran them.
- **Experimental, CLI only:** per-account hourly database restore from the on-server MariaDB
  snapshots (`points <account> db --hourly`, `restore-unit … --db-snapshot hourly:<gen>/<point>`).
  Not yet tested; not in the console.

### Fixed
- Restore of CageFS-caged accounts verified (CloudLinux), checked from inside the cage.
- Release tarballs are built only from the tag, with fixed timestamps and ownership: the same
  tag gives the same files everywhere (the archive bytes can differ between git/tar versions).

### Tested on
CloudLinux 8.10 + DirectAdmin 1.713 (with CageFS), restic 0.19.1 — see
[`tests/README.md`](https://github.com/Velocity-Host-Pty-Ltd/kiss-backup-client/blob/v0.2.0/tests/README.md).

### Install / upgrade
```bash
sha256sum -c kiss-backup-client-0.2.0.tar.gz.sha256
tar xzf kiss-backup-client-0.2.0.tar.gz && cd kiss-backup-client-0.2.0
sudo packaging/install.sh            # upgrades in place, keeps your configuration
```
